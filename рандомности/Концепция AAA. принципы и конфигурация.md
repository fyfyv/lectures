архитектуры и дизайн сетей

концепция AAA представляет механизм управления сетевой безопасности, включает в себя следующие процессы:
1) аутентификация[^1]
2) авторизация [^2]
3) аудит(учет)[^3]
[^1]: определяет какие пользователи могут получить доступ к сети.
[^2]: разрешает пользователю доступ к определенным сервисам
[^3]: процесс записи действий по использованию сетевых ресурсов

общая архитектура AAA включает: пользователей, сервер сетевого доступа(nas), сервер AAA.
сервер сетевого доступа(nas) собирает и осуществляет управление запросами пользователей на доступ, и делает это централизованно. На данном сервере создается несколько доменов для менеджмента пользователей. Различные домены могут быть связаны с разными схемами AAA.

схему AAA будут отличаться способом организации аутентификации авторизации и аудита. AAA поддерживает 
3 режима аутентификации:
1) без аутентификации - пользователям полностью доверяют и их проверка не выполняется, этот режим используется крайне редко в целях безопасности
2) локальная аутентификация -  информация о локальном пользователе, включая имя, пароль и атрибуты настраивается на сервер сетевого доступа nas, в этом случае nas выполняет функции сервера AAA - плюсы( возможность быстрой обработки с низкими эксплуатационными расходами) минусы(объем хранимой информации ограничен аппаратными характеристиками устройства(у роутера очень мало памяти для хранения всех данных)), данный режим часто используется для управления пользователями вошедшими в систему через telnet, ssh или ftp
3) удаленная аутентификация - вся информация о пользователе, включая имя пароль и атрибуты, будет обрабатываться на сервере AAA.  удаленная аутентификация может реализовываться при помощи протокола radius, hwtacacs, nas функционирует как клиент для связи с сервером radius
3 схемы авторизации:
1) без авторизации - пользователь прошедшие проверку имеют неограниченные права доступа в сети
2) локальная авторизация - выполняется на основе конфигурации домена на сервере сетевого доступа
3) удаленная авторизация - авторизация radius применяется только к пользователям аутентифицированных сервером radius, поскольку radius объединяет аутентификацию и авторизацию, то авторизация не выполняется отдельно, при использовании удаленной авторизации пользователи могут получать информацию об авторизации как с сервера AAA(radius) так и с сервера nas, однако приоритет информации от nas ниже чем информация с сервера AAA 
информация об авторизации будет включать название группы пользователей, идентификатор vlan id, номер acl(списки контроля доступа)

аудит 2 схемы:
1) без учета - журнал действий(учета, аудита) не создается
2) удаленный учет - осуществляется через сервер radius
