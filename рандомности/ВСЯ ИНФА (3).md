# FHS и каталоги
***FHS (Filesystem Hierarchy Standard)*** - это стандарт, определяющий структуру и содержание файлов и каталогов в Linux. Это система, по которой удобно отсортированы все файлы в системе.

==Основные каталоги FHS:==
- **/** - Корневой каталог. В нём хранятся все основные каталоги FHS
- **/bin** - Содержит основные исполняемые файлы (бинарные файлы, бинарники, утилиты) для работы пользователя (в основном в терминале). Например `ls`, `cp` и так далее
- **/sbin** - Содержит системные утилиты для работы администратора. Например `reboot` и так далее.
- **/boot** - Содержит утилиты и информацию для загрузчика и ядра ОС
- **/dev** - Содержит специальные файлы для предоставления доступа ко внешним устройствам или виртуальному оборудованию
- **/etc** - Содержит файлы конфигурации системных и пользовательских утилит
- **/home** - Каталог с каталогами пользователей. В каталоге пользователе хранится информация для пользователя
- **/lib** и **/lib64** - Содержат библиотеки, необходимые для работы **/bin** и **/sbin**
- **/media** - Точка монтирования для съёмных носителей, например USB-накопителей.
- **/mnt** - Временная точка монтирования для администратора. 
- **/opt** - Каталог для сторонних приложений, который от слова совсем не являются частью системы. Нужен для установки программ в отдельные каталоги
- **/proc** - Виртуальная файловая система, которая содержит информацию обо всех процессах
- **/sys** - Виртуальная файловая система, которая содержит информацию об аппаратной части, системе и драйверах
- **/root** - Домашний каталог суперпользователя (администратора). Он вынесен, так как главнее, поэтому находится не в **/home**
- **/run** - Каталог временных файлов о работе системы, процессах, службах и подобном. Очищается при перезагрузке системы.
- **/tmp** - Каталог временных файлов которые могут появляться пользователем, сторонними программами. Например там могут быть временные картинки для их отображение в какой-то утилите. Очищается при перезагрузке системы или с какой-то периодичностью, зависит от настроек системы
- **/srv** - Содержит данные для предоставления сервисам, например веб-серверы или FTP
- **/usr** - Содержит пользовательские утилиты и программы.
	- **/usr/bin** - Сами исполняемые файлы утилит и программ
	- **/usr/lib** - Библиотеки для **/usr/bin**
	- **/usr/local** - Программы и утилиты, установленные вручную
	- **/usr/share** - Данные, не зависящие от своего местонахождения (например, документация, иконки)
- **/var** - Содержит изменяющиеся файлы, журналы, базы данных, и так далее
# Процесс запуска ПК
1. Нажимается кнопка пуск (Power), подаётся электричество все все необходимые компоненты компьютера (материнская плата, блок питания, оперативная память...)
2. Если всё хорошо, и питание стабильное, то блок питания отправляет сигнал *Power Good* материнской плате, говоря о том, что нужно переходить на следующий шаг
3. Запускается встроенное в материнскую плату программное обеспечение, которое отвечает за начальную загрузку аппаратных компонентов (за их работу). В настоящее время таких два: BIOS (basic input/output system), и UEFI (Unified Extensible Firmware Interface). Эти программы запускают, а иногда и настраивают некоторые компоненты ПК, но их основная цель заключается не в этом. Они должны проверить работоспособность каждого из компонентов, а после найти загрузочный носитель операционной системы, для её дальнейшей загрузки. В сводке расписано различие BIOS и UEFI.
	![[Pasted image 20250109011153.png]]
	Что такое MBR (Master Boot Record) и GPT (GUID Partition Table)? Это два разных формата таблиц, которые хранят информацию о разделении диска, как данные там организованы и главное, как ОС получает к ним доступ. Это грубо говоря справочник для BIOS и UEFI соответственно.
	![[Pasted image 20250109011550.png]]
	**ESP (EFI System Partition)** — это специальный раздел на жёстком диске или SSD, используемый в системах с **UEFI (Unified Extensible Firmware Interface)**. Он содержит файлы, необходимые для запуска операционной системы, а также другие программы, связанные с загрузкой.
4. После загрузки BIOS/UEFI, эта программа начинает POST (Power-of Self-test). Проверку аппаратной части на работу. Видели наверное, при включении пк на секунду все лампочки начинают мигать, и подобное. Вот это оно и есть. Если всё успешно, заходим в таблицу разделов MBR (для BIOS) или GPT (для UEFI), и считываем загрузочное устройство по порядку, который находится в *boot order* (эта та тема, которую ты изменяешь когда загрузочную флешку ставишь чтоб ОС поставить), идём по boot order и пытаемся запустить загрузочные файлы. Если на устройстве таких нет, переходим к следующему диску. Именно поэтому даже если вы не поменяли boot order, и оставили там свою загрузочную флешку, все равно запуститься загрузчик с вашего диска, куда вы установили ОС. (Кстати говоря, boot order и информация, похожая на него, хранится в материнской плате в CMOS)
5. С загрузочного устройства запускается загрузчик (Bootloader). Загрузчик - это тоже программа, которая, логично, загружает операционную систему. Для Linux сейчас популярным является загрузчик GRUB, а для Windows - Windows Boot Manager. Загрузчик передаёт управление ядру ОС для дальнейшей работы.
6. Ядро начинает работу драйверов устройств, устанавливает управление процессором и памятью (да и другими устройствами), монтирует корневую файловую систему (`/` в Linux и `\C:` в Windows). Передаёт управление программам начальной загрузки.
7. Программы начальной загрузки (системы инициализации) зависят от операционной системы. Сейчас популярны: `systemd`, `SysVinit`, `OpenRC`. ![[Pasted image 20250109103322.png]]
Они запускают все важные службы и процессы, настраивают пользовательскую среду.
8. После этого загружается графическая оболочка. Для Windows всё стабильно - Explorer. А для Linux вот популярные варианты: X11, Wayland и так далее.
9. После этого загружаются пользовательские настройки (обои, иконки, и так далее). Открываются программы для автозапуска
10. Пользователь получает доступ к ОС.
# Файловые системы, файлы в Linux
В Linux всё есть файл. Буквально. Папка? Нихуя, это файл. Флешка или диск? Нихуя, это тоже файл. Короче, файлы вообще всё. И это удобно, потому что нет какой-то абстракции, а только чёткие и ясные формулировки.
==Бывают, очевидно, несколько видов файлов:==
- *Обычные файлы.* По сути всё то, что не подходит под описание ниже. Но это то, чем мы пользуемся. Всякие картинки, музыка, текстовые файлы - всё это обычные файлы. Определяются тире командой `ls -l`
- *Блочные устройства*. Предоставляют функционал для чтения и записи данных у устройства по блочно. По сути и являются файлами устройств, которые нужны для таких вещей (всякие флешки, диски и т.д.). Определяется `b` командой `ls -l`
- *Символьные устройства*. Предоставляет функционал для работы с устройствами, которые работают данные побайтово (например клавиатура, последовательный порт и т.д.). Определяется символом `c` командой `ls -l`
- *Символьные ссылки*. Файлы, которые хранят ссылку на другие файлы. По сути ярлыки в Windows. При обращении к символьным ссылкам, ОС перенаправляет на ссылаемый файл. Обозначается `l` командой `ls -l`
- *Директории*. Используются для организации и хранения других файлов и директорий. Определяется буквой `d` командой `ls -l`
- *Именованные туннели/pipes/FIFO*. Эти файлы являются прямой аналогией pipes из мультипроцессорности в Python, и FIFO из Queue. Нужны для обмена данными из одного файла в другой (только в одну сторону). Создаются командой `mkfifo <pipe name>`. Обозначаются буквой `p` в `ls -l`
- *Сокеты*. Сокеты похожи на туннели, за тем исключением что могут передавать данные с разных машин, и в обе стороны. Чаще всего используются для реализации сетевых приложений. Определяется `s` в `ls -l`

==Популярные файловые системы, и немного про них:==
- **ext2 (Second Extended File System)** - Устаревшая версия, которая была обновлением для оригинальной ext
- **ext3** - Увеличенные характеристики. Новые режимы журналирования
- **ext4** - Современная файловая система, повсеместно используемая в Linux как основная. Поддерживает расширенную аллокацию блоков, журналирование, дефрагментацию и тексты меток файлов.
- **xfs** - Отлично подходит с большими файлами и массивами данных
- **btrfs (B-tree File System)** - Грубо говоря объединение ext4 и xfs в одно, и интересным алгоритмам через бинарные деревья.
- **zfs (Zettabyte File System)** - Размер файла и тома: до 256 квадриллионов зеттабайт.
- **ReiserFS** - Лучше всех работает с маленькими файлами.
- **fat32** - Старая файловая система Windows, но всё ещё используется во всяких флешках и подобных. Максимальный размер файла - 4 гб. 
- **ntfs (New Technology File System)** - Основная файловая система Windows. Просто пизже во всём чем fat32 (кроме, пожалуй, совместимости).

# Команды
- `ls` - отображает файлы в текущей директории. Основные флаги: `-a`, показывает даже скрытые файлы, которые начинаются с точки; `-l`, показывает подробную информацию о файлах, в том числе права доступа; `-1`, показывает за одну строку один файл, чисто для красоты
- `pwd` - выводит директорию где открыт терминал
- `mkdir <path>` - создаёт директорию по пути `<path>`
- `touch <path>` - создаёт файл по пути `<path>`
- `rmdir <path>` - удаляет директорию по пути `<path>
- `rm <path>` - удаляет файл по пути `<path>`
- `echo "<text>"` - возвращает текст, можно сразу запихнуть в какой-нибудь файл через клювики `>` (очистить и записать) или `>>` (добавить в конец файла)
- `cd <path>` - перейти в директорию по пути `<path>` (перейти для терминала, вывод `pwd` сменится)
- `hwclock` - возвращает RTC (Real Time Clock)
- `date` - возвращает дату в удобном формате
- `clear` - очищает консоль
- `emerge <portage>` - загружает из зеркал, что находятся в `/etc/portage/make.conf` определённый пакет *portage*. Имеет много флагов, вот популярные: `--ask`, спрашивает перед установкой отдельных компонентов пакета, иногда без этого не получится корректно установить пакет; `--sync`, без `<portage>` синхронизирует текущие пакеты с пакетами из зеркал; `--config`, установить так же файлы конфигурации у `portage`; `--autounmask`, автоматически размаскирует пакет
- `genkernel all` - начинает автоматическую сборку ядра из всех модулей
- `grep <pattern> <filename>` - возвращает строки найденных шаблонов `<pattern>` в файле `<filename>`. Шаблоном выступает регулярка
- `locale-gen` - обновляет локали (`/etc/locale.conf)
- `nano <filename>` - Открывает файл по пути `<filename>` в текстовом редакторе *nano*
- `cp <copypoint> <pastepoint>` - Копирует файл/директорию по пути `<copypoint>` и вставляет его с новым названием в `<pastepoint>`
- `env-update` - Обновляет и синхронизирует скрипты о переменных окружения в директории `/etc/profile.d/`
- `etc-update` - Обновляет и синхронизирует файлы конфигурации в `/etc/`
- `source <executable filename>` - Запускает файл `<executable filename>` в текущей сессии, не создавая новый процесс.
- `export <NAME>=<VALUE>` - Создаёт или изменяет на время текущего сеанса переменную окружения с именем `<NAME>` и значением `<VALUE>`
- `chroot <root>` - change root, меняет корневой каталог. Используется в основном для тестирования, изолирования директорий
- `chmod <modes> <file>` - изменяет права доступа для владельца, групп и остальных для файла `<file>`
- `lsblk` - выводит в терминал все разделы и устройства
- `chown <owner>:<group> <file>` - изменяет владельца и группу у файла
- `mount <device file>` - монтирует файл устройства
- `unmount <device file>` - размонтирует файл устройства
- `fdisk` - Fixed Disk. Утилита для создания разделов диска в терминале
- `cfdisk` - Curses Fixed Disk. Утилита для создания разделов диска в терминале с более удобным интерфейсом на основе библиотеки Curses.
- `mirrorselect` - утилита для установки зеркал для скачивания исходников для Gentoo Linux и ей подобных
- `mirrorselect -i -o >> /mnt/gentoo/etc/portage/make.conf` - результат mirrorselect запишется в файл конфигурации пакетов для gentoo
- `links <link>` - браузер в терминале
- `tar` - Tape ARchive. Утилита предназначенная для создания, просмотра и извлечения файлов из архивов с расширением .tar или с расширениями дополнительных утилит, например .tar.xz. -x - для извлечения. -c - для создания. -f для указания названия файла. -p - для сохранения прав доступа. -v - для вывода подробной информации о каждом файле: `tar -cf <archive name> <folder that archive from>` - создание.  `tar -xvpf <arcive name>` - извлечение данных из архива
- `mkswap <device file>` - форматирует файл устройства таким образом, чтобы это был файл подкачки
- `swapon <device file>` - включает файл подкачки 
- `apt` - более новая служба управления пакетами
- `blkid <device file>` - выводит UUID (Universally Unique Identifier - уникальный идентификатор, который присваивается диску или разделу) файла устройства а так же много прочей информации о блочных устройствах (Block Id)
- `resize2fs <device file> <size>` - увеличивает размер файловой системы ext2, ext3 или ext4 в файле устройства до размера `<size>`. Если `<size>` не указать, размер будет расширен до размера раздела
- `apt-get` - старая служба управления пакетами
- `apt update` - синхронизирует пакеты с зеркалами и репозиториями. По сути обновляет пакеты до последних версий
- `apt upgrade` - устанавливает обновления. Если `apt update` нам сообщает о том, что есть обновления, то эта команда их устанавливает
- `epel` - Extra Packages for Enterprise Linux. Репозиторий с множеством дополнительных пакетов
- `rc-service` - команда для управления службами в системе инициализации Openrc (Gentoo)
- `rc-update` runlevels default - обычные программы которые загружаются после системных служб, а boot запускается сначала
- `mkfs.<filesystem> <volume>` - Форматирует раздел в файловую систему `<filesystem>`
- `/usr/bin/mysql_secure_installation`
- `USE="ithreads ssl apache2" emerge apache` - устанавлиает apache с возможностью многопоточности, ssl (для https), и версией apache2
- `ip -br a` - выводит краткую информацию о IP сетевых устройств
- `vgcreate <group name> <volume 1> [volume 2...]` - создаёт группу томов
- `pvcreate <volume name>` - создаёт физический том
- `pvdisplay` - отображает все физические тома и информацию о них
- `vgremove <vg name>` - удаляет группу томов
- `vgextend <vg name> <pv name> [pv name...]` - добавить физические тома в группу томов
- `vgdisplay` - отображает информацию обо всех группах томов
- `vgreduce <vg name> <pv name> [pv name...]` - удалить физические тома из группы томов
- `useradd <username>` - создаёт нового пользователя
- `usermod` - изменение пользователя. -a - добавить в группу, -G - название группы. Прим: `usermod -aG <group name> <username>` - добавить пользователя в группу
- `groupadd <group name>` - создаёт группу пользователей
- `lvcreate -n <lv name> <group name>` - создать логический том. -L - указать размер тома. --snapshot - создать моментальный снимок: `lvcreate --snapshot -n <snapshot name> -L <snapshot size> /dev/<group name>/<lv name>`
- `lvremove <lv name>` - удаление логического тома
- `dispatch-conf` - утилита для решения конфликтов между файлами конфигурации после обновления. Как ошибки мержа в гите
- `ntpd –q` - однократно синхронизирует время с ntp сервером и выводит всю информацию о его работе
- `lvextend -L +<size> <lv file>` - увеличивает размер логического тома
- `USE=”-doc symlink” emerge gentoo-sources` - устанавливает исходники gentoo с use-флагами: -doc - отключает установку документации, symlink - создаёт символическую ссылку /usr/src/linux указывающую на установленные исходные коды ядра
- `mdadm --create <raid file> --level=<level> --raid-devices=<count of volumes> [v_file1 v_file2 ... v_file<count_of_volumes>]` - Multiple Device Admin. Утилита для управления программными RAID-массивами. --level - уровень RAID. --raid-devices - количество томов в массиве. --remove - удаляет том. --verbose - отображает подробную информацию: `mdadm --remove <raid file> <volume file>`
- `grub-install <device file>` - Grand Unified Bootloader install. В качестве `<device-file>` ставится раздел загрузчика (`boot`)
- `groups <username>` - выводит все группы пользователей. Если указать `<username>` то будет вывод всех групп у конкретного пользователя
- `emerge --autounmask-write os-prober grub:2` - os-prober - утилита, которая автоматически обнаруживает операционные системы, установленные на других разделах диска. Это нужно для GRUB для создания меню загрузки с несколькими ОС, например когда на компе одновременно и Linux и Windows. Эта команда устанавливает os-prober и grub:2 (двоеточие говорит о версии пакета). Автоматически размаскирует эти пакеты. Маскировка пакетов - запрет на их установку по тем или иным причинам, например, обязательное использование определенных use-флагов.
- `USE="apache2 mysql mysqli postgres pdo zip unicode cgi curl gd json ssl session flatfile fileinfo opcache" emerge --ask php` - Устанавливает `php` и зависимости между `php` и `apache2 mysql mysqli postgres pdo zip unicode cgi curl gd json ssl session flatfile fileinfo opcache`. USE флаги в целом используются для индивидуальных настроек пакетного установщика
- `ntpdate <hostname>` - подключиться по `ntp` к `<hostname>`
- `uname` - показывает информацию о системе. Название ОС и так далее. Там много опций.
- `lvs` - выводит все логические тома
- `fallocate -l <size><MB, GB, etc.> <filename>` - Используется для резервирования пространства на диске в размере `<size><MB, GB, etc.>` для файла по пути `<filename>`. При этом сам файл не заполняется данными. Это удобно, например, для создания файла подкачки.
- `dnf` - пакетный менеджер для дистрибутивов Linux на основе RPM (Red Hat Package Manager)
- `semenage fcontext --add --type "samba_share_t" /srv/share` - команда используется в системе безопасности SELinux (Security-Enhanced Linux) для управлением контекстами ("контекст" в данном контексте это набор метаданных, которые определяют, какие права и политики применяются к файлу, процессу или другому объекту в системе) файлов. Эта команда добавляет новое правило контекста типа `"samba_share_t"` (для обших ресурсов samba) по пути `/srv/share`. Это нужно, чтобы samba смогла получить доступ к файлам в этом каталоге
- ==Контексты SELinux== - это набор метаданных, которые определяют, какие права и политики применяются к файлу, процессу или другому объекту в системе. Имеет следующий вид: `system_u:object_r:samba_share_t:s0`. **samba_share_t** — **тип (Type)**, который определяет политику доступа. В нашем случае `samba_share_t` говорит, что этот объект используется для Samba. (на другие похуй, их в лабах нет)
- `restorecon -R /srv/share` - Рекурсивно обновляет текущий контекст файлов в соответствии установленным контекстом команды `semenage fcontext`
- `free` - показывает информацию о памяти системы. `-h` выводит данные в удобном для человека формате
- `<команда> | tee <filename>` - выводит результат команды `команда` в `stdout` а так же сохраняет в файл `filename`
- `smbpasswd -a <username>` - используется для **управления паролями пользователей Samba**. Она позволяет изменять или задавать пароли для учетных записей Samba, которые хранятся отдельно от системных учетных данных Linux. Добавит пользователя `username` в БД и запросит создание нового пароля
- `firewall-cmd --get-active-zones` - используется для **отображения активных зон в `firewalld`**. Зоны - это **набор правил**, которые определяют, какие соединения разрешены или заблокированы для определенных интерфейсов сети. Бывают *public* (частично ограниченные), *home* (чуть больше прав), *work* (для корпоративных сетей) и *trusted* (полный доступ)
- `whoami` - возвращает имя текущего пользователя. Буквально “кто я?”
- `mkfifo <filename>` - Создаёт именованный туннель с именем `<filename>`
- `webapp-config -h localhost -d wordpress -I wordpress 6.7.1` - нужна для того, чтобы установить `wordpress` на виртуальный хост `localhost` с версией `6.7.1`. Эту команду выводит терминал после установки `wordpress`.
- `mysql -u root -p` - Заходит в базу данных. `-u`, имя пользователя, в данном случае `root`, `-p` - нужен пароль при входе.
- `ln <file> <link>`  - используется для создания ссылок на файлы и директории. Она позволяет создать **жёсткую** (hard) (создаёт другую запись в файловой системе, которая указывает на тот же инод, что и оригинальный файл. Удаление оригинального файла не затронет жёсткую ссылку) или **символическую** (soft) (это отдельный файл, который содержит путь к оригинальному файлу. Если оригинальный файл удалён, символическая ссылка становится "битой" (неработающей)) ссылку. Для создания жёсткой ссылки нужно лишь указать `file` и `link`. Для символической ссылки используется опция `-s`.
- `stat <filename>` - выводит информацию о файле по пути `<filename>`

# Основные файлы конфигураций
- ==/proc/mdstat==
	  **Файл содержит информацию о текущем состоянии всех RAID-массивов, запущенных в системе:**
	- Статус массивов.
	- Уровень RAID (RAID 0, RAID 1, RAID 5 и т. д.).
	- Количество активных и отсутствующих устройств.
	- Прогресс синхронизации или восстановления массива.
	- Текущее состояние дисков.
	**Параметры:**
	- Personalities — показывает, какие типы RAID поддерживаются.
	- md0, md1 — имена массивов.
	- raid1 — тип RAID.
	- sda1[0], sdb1[1] — устройства, входящие в массив (номера в квадратных скобках — их индексы в массиве).
	- [2/2] — количество активных устройств из общего числа.
	- [UU] — состояние массива:
		- U — диск активен.
		- _ — диск отсутствует или неисправен.
- ==/etc/systemd/journald.conf==
	  **Файл конфигурации журналирования системы инициализации systemd.
	  Параметры:**
	  - Storage= | Где хранить журналы | volatile (оперативка - /run/log/journal/), persistent (диск - /var/log/journal/), auto, none

	  - RuntimeMaxUse= | Максимальный размер временных логов | Размер (например, 100M)
- ==/etc/fstab (file system table)==
	  **Файл считывается системой для автоматического монтирования файловых систем. Устроен следующим образом:**
	<что монтируем (блочное устройство)> <путь монтирования> <файловая система> <параметры> <резервное копирование (0 - нет, 1 - да)> <приоритет проверки файловой системы (0 - не проверять, 1 - root, 2 - остальные>
	**Параметры:**
	- **defaults** Использовать настройки по умолчанию (rw,suid,dev,exec,auto,nouser,async)
	- **rw** / **ro** — Разрешено чтение и запись / Разрешено только чтение
	- **suid** / **nosuid** — Разрешение / Блокировка работы suid, и sgid бит
	- **dev** / **nodev** — Интерпретировать / не интерпретировать блок специальных устройств на файловой системе.
	- **exec** / **noexec** — Разрешить выполнять двоичные файлы находящиеся на этом диске / Запретить
	- **auto** / **noauto** — Устройство будет устанавливаться автоматически при загрузке / Не будет
	- **nouser** / **user** — Запрещение монтирование от всех кроме root (nouser) / Разрешение монтировать от лица любого пользователя
	- **async** / **sync** — Запись и чтение на диске будут производиться асинхронно / Синхронно
- ==/etc/portage/make.conf==
	  **Это основной конфигурационный файл системы Gentoo Linux, который используется для настройки параметров сборки пакетов с помощью системы управления пакетами Portage.**
	*Параметры:*
	- CHOST - Определяет целевую архитектуру и ABI (Application Binary Interface) для компиляции программ. (прим: `"x86_64-pc-linux-gnu"`)
	- CFLAGS and CXXFLAGS - Опции компилятора для C и C++ соответственно. Определяют оптимизации и специфичные параметры сборки. (прим: `"-O2 -march=native -pipe"`: `-02` - уровень оптимизации, `-march=native` - автоматически выбирает оптимальные инструкции для процессора, `-pipe` - ускоряет компиляцию, используя каналы вместо временных файлов)
	- CONFIG_PROTECT - Позволяет Portage не перезаписывать конфигурационные файлы при обновлениях. Если этот параметр настроен, файлы с изменённой конфигурацией сохраняются с окончанием `.cfg0000_*`.
	- FEATURES - Определяет дополнительные возможности Portage. Опции
		  - `parallel-fetch` — загружает пакеты заранее.
		  - `ccache` — использует кеш компиляции.
		  - `sandbox` — защищает файловую систему от потенциально вредных сборок.
		  - `userfetch` — выполняет загрузку пакетов от обычного пользователя.
	- GENTOO_MIRRORS - Список зеркал для загрузки исходников. (прим: "http://mirror.yandex.ru/gentoo-distfiles/")
	- MAKEOPTS - Определяет количество потоков при компиляции. `-jN`, где N - кол-во потоков процессора + 1 (2x для Ryzen)
	- EMERGE_DEFAULT_OPTS - Дополнительные опции по умолчанию для `emerge`. (`--jobs=4` — количество параллельных компиляций. `--keep-going` — продолжает установку, даже если есть ошибки.)
	- PORTAGE_SCHEDULING_POLICY - Определяет планировщик процессов для `emerge`. `idle` — снижает нагрузку на систему. `normal` — обычный режим.
	- PORTAGE_TMPDIR - Каталог для временных файлов компиляции. (прим: "/var/tmp")
	- DISTDIR - Каталог для скачанных исходников. (прим: "/var/cache/distfiles")
	- PKGDIR - Каталог для бинарных пакетов (`emerge -b`). (прим: "/var/cache/binpkgs")
		- USE - Глобальные флаги USE, определяющие зависимости и функциональность пакетов. (прим: "alsa pulseaudio nls" <=> поддержка ALSA, pulseaudio и локализации) 
	- ACCEPT_LICENSE - Определяет, какие лицензии принимать при установке пакетов. ("\*" - для всех лицензий)

		│   ├── Los_Angeles
		│   ├── Chicago
		│   ├── ...
		├── Asia/
		│   ├── Tokyo
		│   ├── Shanghai
		│   ├── Novosibirsk
		│   ├── ...
		├── Europe/
		│   ├── Moscow
		│   ├── Berlin
		│   ├── London
		│   ├── ...
		├── UTC
		└── Etc/

- ==/etc/ntp.conf==
	  **Используется для конфигурации сервиса NTP (Network Time Protocol) в системах Linux и Unix. NTP позволяет синхронизировать системное время с внешними временными серверами, обеспечивая точность и согласованность времени на компьютерах в сети. Этот файл управляет настройками, связанными с синхронизацией времени.**
	  *Параметры*:
	  - `server` - Указывает NTP-сервер, с которым будет синхронизироваться ваше устройство. Можно использовать как конкретные IP-адреса, так и доменные имена серверов. (прим: `server 0.pool.ntp.org`)
	  - `pool` - Используется для указания пула серверов времени. Это специальная настройка, которая автоматически выбирает несколько серверов из пула для повышения надёжности. (прим: `pool 0.centos.pool.ntp.org iburst`. Здесь `ipurst` - это опция, которая ускоряет начальную синхронизацию с сервером.)
	  - `restrict` - Этот параметр используется для задания ограничений на доступ к серверу времени.
- ==/etc/portage/package.use/www-apps==
	**Файл `/etc/portage/package.use/www-apps` в Gentoo используется для управления настройками USE-флагов для пакетов, относящихся к категории `www-apps`. USE-флаги в Gentoo — это механизм для включения или исключения функциональности в пакете, позволяя адаптировать его под нужды пользователя. Категория `www-apps` включает в себя пакеты, которые связаны с веб-приложениями, например, серверы приложений, CMS, инструменты для веб-разработки и т.д.
	В данном случае, файл `/etc/portage/package.use/www-apps` позволяет задавать USE-флаги для пакетов из категории `www-apps`, чтобы настраивать, какие функции или модули будут включены при установке этих пакетов.**
	*Параметры*:
	- Каждая строка задаёт USE-флаги дял определённого пакета. Имеет следующий вид: `<category>/<package> <use-flags>` (прим: `www-apps/wordpress mysql multilib`)
- ==/var/www/localhost/htdocs/wordpress/wp-content==
	**В этой папке хранятся все пользовательские файлы, такие как темы, плагины, загруженные медиафайлы и другие компоненты, которые не являются частью ядра WordPress. Это позволяет разделить системные и пользовательские данные.**
	*Имеет следующую структуру*:
	- `themes` - Содержит все установленные темы для вашего сайта WordPress.
	- `plugins` - Здесь находятся все установленные плагины, которые расширяют функциональность WordPress.
	- `uploads` - Здесь хранятся все медиафайлы, загруженные пользователями через админку WordPress, такие как изображения, видео, аудиофайлы и документы.
	- `languages` - Эта папка используется для хранения языковых файлов для WordPress, плагинов и тем. Если вы хотите установить локализацию на другие языки, файлы переводов будут размещены здесь.
	- `mu-plugins` - Это папка для "Must-Use" плагинов (обязательных плагинов), которые загружаются автоматически и всегда активированы в WordPress, даже если они не видны в разделе администрирования плагинов.
	- ``upgrade`` - Эта папка используется для временного хранения файлов, которые создаются во время процесса обновления WordPress, тем или плагинов.
- ==/var/www/localhost/htdocs/wordpress/wp-config.php==
	**Используется для настройки различных параметров сайта, подключения к базе данных, безопасности и других настроек. Этот файл лежит в корне установки WordPress и должен быть настроен правильно для корректной работы сайта.**
	Функцией define мы настраиваем этот файл. Например, для настройки пользователя базы данных: `define( 'DB_USER', 'пользователь_базы_данных' );`
- ==/etc/samba/smb.conf ==
	**Samba позволяет интегрировать сервер Linux или UNIX в сети с операционными системами Windows, предоставляя возможность совместного использования файлов и принтеров. В этом файле настраиваются параметры, связанные с обменом файлами и доступом к ресурсам.**
	*Разделы*:
	- `[global]` - содержит настройки, которые применяются ко всей системе и ко всем ресурсам, которые предоставляет Samba. Это основные параметры для настройки службы.
		- **`workgroup`** — Название рабочей группы (для Windows). Это название группы, к которой будут присоединяться ваши устройства.
		- **`server string`** — Описание сервера, отображаемое в сетевых ресурсах.
		- **`netbios name`** — Имя NetBIOS вашего сервера в сети.
		- **`security`** — Определяет уровень безопасности. 
		- **`map to guest`** — Определяет, как Samba будет обращаться с неавторизованными пользователями.
		- **`log file`** — Указывает путь к файлу журнала для Samba.
		- **`max log size`** — Максимальный размер лог-файла (в килобайтах).
		- **`dns proxy`** — Включает или отключает использование DNS в Samba. ]
	- `[share]` - В этой секции настраивается доступ к папкам и файлам, которые будут доступны пользователям.
		- **`path`** — Путь к папке, которая будет доступна по сети.
		- **`browseable`** — Определяет, будет ли этот ресурс виден в сети.
		- **`writable`** — Указывает, разрешено ли пользователям записывать в эту папку.
		- **`guest ok`** — Разрешает или запрещает доступ гостевых пользователей (пользователей без аутентификации).
		- **`create mask`** — Маска прав доступа для создаваемых файлов.
		- **`directory mask`** — Маска прав доступа для создаваемых директорий.
		- **`valid users`** — Указывает, какие пользователи имеют доступ к данному ресурсу.
