### Системы инициализации

1. **Что такое система инициализации, для чего нужна?**
	- Первый пользовательский процесс (`PID=1`), который запускается ядром Linux. Отвечает за запуск и остановку служб(демонов), монтирование файловых систем.
	ㅤ
2. **Какая система инициализации используется в Slackware?**
	- **BSD init** - аналог SysV init, который используется в FreeBSD, OpenBSD, NetBSD и т.д. Управление происходит в конфигурационном файле `/etc/rc.conf`
	ㅤ
3. **Какая система инициализации в Gentoo?**
	- Open**RC** - система инициализации для Gentoo и Alpine. Управление службами осуществляется с помощью команды **rc**-service <действие> <служба>.
	ㅤ
4. **Какая система инициализации в Ubuntu?**
	- **System**d - система инициализации для Debian-подобных систем. Управление службами осуществляется с помощью команды **system**ctl <действие> <служба>.
	ㅤ
5. **Что такое systemd?**
	- **Systemd (Debian-подобные)** — современная система инициализации, с параллельным запуском служб.
	ㅤ
6. **Какие еще системы инициализации есть?**
    - **Systemd** - параллельный запуск служб.
    - **SysV init** - последовательный запуск через скрипт в `/etc/init.d/`.
    - **OpenRC** - альтернатива init-системы
    ㅤ
7. **Совместимы ли системы инициализации друг с другом? Можно ли её поменять?**
    - **Не совместны**, т.к **они разные во всем**, допустим **SysV init** использует специальные скрипты `/etc/init.d/`, а для **Systemd** хватает одной команды `systemctl`. У них разный синтаксис и запуск служб у них **разный**, тот же **SysV** использует **последовательный запуск** служб, а **Systemd** **параллельный**.
    - **Да, но это сложно и может привести к неработоспособности системы.** Поэтому лучше учить синтаксис или выбирать системы с выбором системы инициализации тот же самый Gentoo.
    ㅤ
8. **Процесс включения системы рассказать (поэтапное объяснение запуска компьютера)**
    1. При нажатии кнопки питания из энергозависимой памяти запускается прошивка BIOS/UEFI и выполняется POST (самотестирование при включение, то есть проверка на неисправности и настройки компонентов).
    2. BIOS/UEFI обнаруживает устройства, подключённые к системе(абсолютно все).
    3. Выбирает устройство, с которого будет загружена система.
    4. BIOS/UEFI запускает загрузчик (GRUB)), который предоставляет меню для выбора операционной системы или загрузки ядра.
    5. После подготовки ядра система переходит в пользовательское пространство. Ядро запускает systemd как первый пользовательский процесс. Он управляет процессами и службами, определяет всё оставшееся оборудование, монтирует файловые системы и загружает рабочий стол.
    6. Systemd активирует целевое состояние по умолчанию при загрузке системы. Также выполняются другие вспомогательные модули. 
    7. Система выполняет набор стартовых скриптов и настраивает окружение.
    8. Пользователям представляется окно входа в систему. Теперь система готова к использованию.

### Загрузка системы и разделы

1. **Расшифровка BIOS и объяснение его**
    - Basic Input/Output System - встроенное ПО, которое обеспечивает начальную загрузку компьютера и взаимодействие между аппаратными компонентами и операционной системой. Без BIOS компьютер не смог бы проверить оборудование и запустить операционную систему.
    ㅤ
    - **B**asic — базовый (работает на низком уровне, близко к "железу").
    
	- **I**nput — ввод (управление устройствами ввода: клавиатура, мышь и др.).
    
	- **O**utput — вывод (управление монитором, дисками, USB и др.).
    
	- **S**ystem — система (обеспечивает работу всей системы при включении).
    ㅤ
2. **Что такое EFI/UEFI, в чем его преимущества?**
    - Современная замена BIOS.
    
	- Поддерживает GPT(Позволяет использовать диски объемом более 2 ТБ), Secure Boot(Защита от вредоносного ПО), загрузку с FAT32-раздела (`/boot/efi`).
    
	- Загружает `.efi-файлы` напрямую (например, `grubx64.efi`).
    ㅤ
3. **Чем отличаются GPT и MBR?**
    - MBR: до 2 ТБ, 4 раздела максимум, нет резервного копирования
    - GPT: Нет ограничения, 128+ разделов, хранит копии таблицы разделов(лучше восстанавливается)
    ㅤ
4. **Аналоги lsblk**
	- fdisk, cfdisk, parted
    ㅤ
5. **Как еще можно найти путь к подключенному устройству (флешке), если не работают lsblk и cfdisk?**
    - Посмотреть командой `ls /dev` устройства, которые подключены
    - Использовать `sudo blkid`, чтобы посмотреть UUID и тип ФС для устройств.
    ㅤ

### Логирование

1. **Что такое журналирование?**
    - Запись событий системы/приложений в логи (например, `/var/log/syslog`). Командой `journalctl` можно посмотреть абсолютно все логи.
    ㅤ
2. **Что такое syslog-ng, что делает?**
    - Это **демон** и **протокол** для сбора и фильтрации логов. Может:
    - Писать логи в файлы.
    - Отправлять их на удалённый сервер.
    - Фильтровать по приоритету(`debug`, `error` и т.д.).
    ㅤ
3. **Чем можно заменить syslog-ng?**
    - journalctl
    ㅤ
4. **Для чего нужна утилита journalctl?**
    - Утилита для просмотра логов `systemd-journald`
    ㅤㅤ
5. **Может ли сама служба syslog-ng отправлять логи и как?**
    - Да, **syslog-ng** может не только принимать, но и **отправлять логи** на удаленные серверы или другие системы. Для этого используются **destination** с настройками сетевого протокола (UDP, TCP, TLS) и **log-пути**, которые связывают источники (source) с назначениями (destination).
    ㅤ
6. **Что такое ротация логов?**
    - Автоматическое архивирование/удаление старых логов (например, через `logrotate`).
    ㅤ
7. **Что означают строки в конфигурационном файле syslog-ng**
    - Конфигурационный файл делится на несколько блоков:
    - `source` - определяет, откуда syslog-ng получает логи (файлы, сокеты, системные журналы).
    - `filter` - позволяет отбирать логи по заданным критериям (уровень, программа, регулярные выражения).
    - `destination` - указывает, куда отправлять логи (файлы, удаленные серверы, БД)
	- `log` - связывает `source`, `filter` и `destination` в единый маршрут обработки.
    ㅤ

### Файловая система и каталоги

1. **Почему мы монтируем именно в /media/cdrom?**
    - Это стандартный каталог для временных устройств (как `/mnt`, но для CD/USB). Потому-что система будет искать устройство именно в этой директории.
    ㅤ
2. **В каком каталоге хранится почта?**
    - Обычно в `/var/mail/username` или `/var/spool/mail/`.
    ㅤ
3. **Что хранится в каталоге /lib?**
    - Содержат библиотеки, необходимые для работы **/bin** и **/sbin**
    ㅤ
4. **Что хранится в /etc?**
    - конфигурационные файлы установленных служб
    ㅤ
5. **Что в файле /etc/hosts?**
    - Сопоставляет IP-адреса с именами хостов (локальный DNS).
    ㅤ
### Утилиты и программы

1. **Чем отличается утилита, программа, служба?**
    - **Программа** - любое ПО, например `firefox`
    - **Утилита** - небольшая программа для администрирования, например `ls`, `grep`
    - **Служба** - фоновая программа (демон), например `sshd`
    ㅤ
2. **Что такое flatpak (и почему это утилита, а не программа или служба)?**
    - Это **утилита**, потому-что она используется для управления пакетами и также можно запускать приложения в виртуальной среде без влияния на основную систему.
      P.s: в ЛР "Управление ПО" мы использовали `flatpak` для установки `PortProton` и после запускали `PortProton` в виртуальной среде `flatpak`
    ㅤ
3. **Назовите программу, которая работает с сетями как NetworkManager**
    - Например `systemd-networkd` - демон для управления сетевыми настройками в Linux. Использует конфигурационные файлы в `/etc/network/`
4. **Какие три утилиты используются для сборки приложения из исходных файлов?** 
    1. `./configure` — проверка зависимостей.
    
	2. `make` — компиляция.
    
	3. `sudo make install` — установка (требует root).
    ㅤ

### Безопасность

1. **Что делает SELinux?**
    - Система безопасности Linux для контроля доступа к файлам и директориям даже имея права root SELinux может заблокировать действия, если оно нарушает политику безопасности.
    ㅤ
2. **Почему его отключают?**
    - Из-за сложности настройки
    ㅤ

### Прочее

1. **Что такое именованный канал?**
    - Файл `FIFO` для передачи данных между процессами.
    ㅤ
2. **Бывает ли неименованный канал и в чем отличие от именованного?**
    - Да, в Linux существуют **неименованные каналы (анонимные каналы, pipes)**, которые создаются с помощью символа `|` (вертикальная черта) в командной строке или программно через системный вызов `pipe()`.
      Например:
      `ls -l | grep ".txt"` - выведет все файлы с расширением `.txt`,
      то есть grep отфильтрует принятые строки из ls и выведет уже итоговый список.
    ㅤ
3. **Что такое репозиторий?**
   - **Репозиторий** (в понимании Linux) - хранилище пакетов, откуда дистрибутивы Linux получают софт. Представлен в виде файла, например: `/etc/apt/sources.list`, где буквально хранятся URL ссылки до репозиториев.
